# Admin

An operational surface in the costume. Scanability comes from the ruled index and the frame, not from a gray app shell.

## Opening

Top bar: mark, word links for the real sections, one paper quick action (the verb the operator came to do), one search field.

Below it, the page title is display type, left, naked. The title is the object being operated, not "Dashboard".

The first viewport contains that title and the one Action. If the work is a queue, the Action is on the queue. If the work is a record, the Action is on the record. It is not a button in a page header miles from the control.

## Body

The work is a grid of framed instruments, the way a generated interface poster is framed:

- A table is a square frame. Header row is mono, uppercase, Ash. Selected row is Paper with Ink text. Empty cells stay empty. One Run or Apply, in Action, sits on the frame, not in a toolbar of icons.
- A queue is columns of square cards inside one frame, column names in mono. A card is a name and a mono status line, not an avatar stack.
- A calendar or timeline is the instrument itself, grid on the well, events as paper or hairline blocks.
- Filters are a segmented control or a mono index, not pills.

Numbers that are real are set in display or title weight beside a mono unit. They are not a row of identical stat cards. If the number is illustrative, say so in the frame.

## States

- Empty: the frame remains. One sentence names what is missing and the recovery. The Action is that recovery.
- Error: a sentence under the field. The border stays Frame. Do not turn it red.
- Loading: the Action reads the verb in progress ("Reading", "Saving"). The control stays visible.
- Dense data: tighten the row, not the page title. The title stays display. The table may use body size, never below the label floor for headers.
